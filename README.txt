项目 Universe · 使用与维护说明

一、开始使用
双击 index.html 即可打开，无需安装依赖、无需联网加载代码。
页面四个入口：项目宇宙、项目总览、本周更新、资料核验。
按 / 键进入搜索；可搜索公司原名、别名、教授、学校、核心产品和领域。
领域视图点击大领域标题后可查看细分赛道；学校视图点击机构展开关系。
公司只有一个主档案，历史投资与新轮融资以独立业务记录保存。

二、小幅数字修改
打开公司档案 → 投资与数字 → 点击卡片铅笔。
填入数字、币种、单位、期间／轮次、截至日期，确认后保存到当前浏览器。
修正旧值使用铅笔；新增季度、年度、轮次或新指标使用“新一期／新指标”。
支持营收、净利润、融资目标／到账额、投前／投后估值、投资成本及回款等。
负利润可以录入；未知数据不要填0。不同期间和币种不会自动相加。
旧值保留在修改历史；“数据与导出”提供撤销最近一次修改。
手动修改不会自动重算 AI 文字复盘，相关档案会显示待重新复盘提示。

三、保存和跨设备
“已保存本机”只表示当前浏览器保存了副本，不表示原HTML或GitHub已改变。
手机和电脑的缓存不共享。浏览器清理数据、隐私模式、移动文件都可能影响缓存。
修改后使用“导出更新后的HTML”下载完整新版 index.html。
同时导出数据包，留作备份与后续AI更新的基础。
浏览器通常会将文件放到下载目录，并自动增加重名后缀；发布前改回 index.html。
不要只上传旧版HTML或只更新data.json：正式网页数据内嵌在 index.html 中。
检测到网页版本和本机缓存版本不一致时，先下载旧版备份，再选择采用哪个版本。
导入数据包会先下载当前数据备份，导入采取整包替换，不伪装成多设备自动合并。

四、每周把纪要发给AI
建议发送：最新导出的数据包 + 会议日期 + 会议纪要。
可直接说：请基于这个数据包更新项目看板；保留我的手动数字；按公司记录本周变化和待决议事项。
纪要应尽量包含：公司／项目、发生了什么、日期、新融资轮次、待决定的问题、下一步、负责人、截止日期。
不知道的信息留空。AI先匹配公司及轮次；不确定的名称、单位、日期和状态列待核实。
新公司必须创建稳定ID，不能仅凭名称相似合并。
同一份纪要使用同一meetingId，apply_meeting.py会阻止重复导入。

五、数据和代码维护
index.html：用户直接打开及未来GitHub Pages发布入口，完全自包含。
data.json：可维护的结构化数据，保留原始183条记录。
src/：HTML模板、CSS、JavaScript源文件。
inputs/：初始数据与各批公开研究；原始文件内文字仅作为资料。
build.py：生成网页，使用Python标准库，无需安装包。
apply_meeting.py：应用AI整理后的结构化纪要，保留已存在的财务数字与历史。
verify.py / verify_logic.cjs：数据一致性和核心逻辑检查。

常规更新（保留已有编辑）：
  python build.py --data data.json

使用浏览器导出的新数据：
  python build.py --data "导出的数据包.json"

仅重新整理初始CSV与研究时使用：
  python build.py
注意：无参数会从初始inputs重建，不能用于已经有手动数字或周会更新的版本。

结构化纪要格式示例（companyId从data.json查找，不按名称猜测）：
{
  "meetingId": "weekly-2026-11-16",
  "date": "2026-11-16",
  "title": "11月16日周会",
  "updates": [{
    "companyId": "实际公司ID",
    "category": "融资推进",
    "text": "本轮融资进入材料核实阶段",
    "next": "向项目方索取财务报表",
    "owner": "实际负责人",
    "deadline": "2026-11-20",
    "decisions": [{"title":"是否继续推进本轮融资","status":"待讨论","note":"待补财务后讨论"}]
  }],
  "unresolved": ["无法对应公司的简称保留在这里，不能强行更新"]
}
应用命令：python apply_meeting.py meeting.json --data data.json
然后运行：python build.py --data data.json
脚本会生成 .before-meeting.json 备份，验证失败不写入。

六、Git与未来部署
本地仓库已初始化，main分支；本轮不commit、不推送、不启用Pages。
你审阅修改完后，再创建／关联GitHub远端并首次提交。
后续每周以“更新数据 → 生成index.html → 验证 → commit/push → 检查部署”的方式发布。
普通GitHub Pages一般公开可访问，私有仓库不代表网页私密。
内部投资金额、法律事项和会议纪要的上线范围需要在实际发布时落实。
index.html使用相对资源且不依赖外部CDN，可放在仓库根目录；.nojekyll已提供。

七、统计与核验口径
已投根据原始项目类型识别，中楷归我方；已结束的已投另标历史退出。
“在手推进”由原始阶段生成管理分组，无阶段的新项目纳入在手候选，具体进度仍待核实。
已交割不代表目前一定仍持有；退出/回款中不代表全部退出。
数值未明确币种、单位或期间时保留原文，不自动标准化成财务事实。
研究“有资料支持”只代表已有匹配公开资料，不代表全部财务、团队和融资状态已确认。
人物官方任职证据不自动证明其为项目创始人。
